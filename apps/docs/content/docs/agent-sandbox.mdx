---
title: Test agents in an isolated instance
description: Run a separate self-hosted Sniptide instance with its own database for agent integration tests, point the CLI, SDKs and MCP at it, and remove it afterwards.
---

Run destructive agent tests and retry experiments against a separate Sniptide instance on your
own machine. Sniptide doesn't offer a hosted sandbox, and a second token for your real account
still reaches that account's data, so it doesn't isolate tests.

## Before you begin

- Docker with the Compose plugin, as for [Run your own Sniptide](/getting-started/self-hosted).
- Free local ports `3001` and `5433`, or other ports you choose below.

## Start the test instance

1. Copy `docker-compose.yml` and `.env.example` into a new directory, separate from any real
   instance.
2. Create `.env` in that directory:

   ```dotenv title=".env"
   BETTER_AUTH_SECRET=<output of openssl rand -hex 32>
   BETTER_AUTH_URL=http://localhost:3001
   SNIPTIDE_PORT=3001
   POSTGRES_PORT=5433
   SNIPTIDE_BIND=127.0.0.1
   ```

   Leave `SHARE_URL` unset, or set it to the same `http://localhost:3001`.
3. Start it under its own Compose project name, which gives it its own containers and database
   volume:

   ```bash
   docker compose -p sniptide-agent-test up -d
   ```

   Never point the test instance at your real database or volume.
4. Open `http://localhost:3001`, create a test account, and under **Settings** > **API tokens**
   create a token with **Write access** and an expiry that covers your tests.

## Point your tools at it

Set these in the agent's or test runner's environment:

```bash
export SNIPTIDE_BASE_URL=http://localhost:3001
export SNIPTIDE_TOKEN=<test token>
```

The CLI and the local stdio MCP server read both variables. For the SDKs, pass the address as the
base URL. For an HTTP MCP client, use `http://localhost:3001/api/mcp` with the header
`Authorization: Bearer <test token>`.

## Verify the target before you write

Confirm that the token belongs to the test account before you run anything that changes data:

```bash
curl -H "Authorization: Bearer $SNIPTIDE_TOKEN" http://localhost:3001/api/v1/me
```

The response must name your test account. To test safe retries, send the same create twice with
the same `Idempotency-Key` header and check that both responses return the same paste id. See
[API reliability](/api-reliability#retry-a-create-safely).

The test instance enforces the same authentication, quotas, storage limits and receipt retention
as any other instance. Use made-up snippets and env values, so failures and logs contain no real
secrets.

## Clean up

- `docker compose -p sniptide-agent-test down` stops the instance and keeps its data for the next
  run.
- `docker compose -p sniptide-agent-test down -v` also deletes its database volume. Run it only in
  the test directory, when you no longer need the fixtures.
- If you keep the instance, revoke the test token when the tests end.
