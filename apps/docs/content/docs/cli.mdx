The `sniptide` CLI captures files from a project into a paste with their folder structure,
restores them in another project, and syncs a project's `.env` with your instance. It calls the
[token API](/api-tokens), prints JSON on request and never prompts, so people and coding agents
can both run it.

## Before you begin

- Node.js 24 or newer.
- An [API token](/api-tokens). Use a read-only token for `pull`, `list`, `search`, `skill` and
  `env pull`. `push`, `env push` and `env delete` need **Write access**.
- An HTTPS address for a self-hosted instance. The CLI allows plain HTTP only on `localhost`.

## Install the CLI

```npm
npm install --global @sniptide/cli
```

Then check that it runs:

```bash
sniptide --version
```

`--version` prints the installed version. Contributors can run the source from a checkout with
`bun run cli <command>`, or build it with `bun --filter @sniptide/cli build` and run
`node packages/cli/dist/sniptide.js`.

## Connect to your account

Choose one way to give the CLI your token.

<Tabs items={["Save the token", "Environment variables"]}>
<Tab value="Save the token">

Pipe the token to `login`, so it never appears in the process list. Add `--base-url` for a
self-hosted instance:

```bash
printf '%s' "$SNIPTIDE_TOKEN" | sniptide login --token-stdin --base-url https://paste.example.com
```

```text
Logged in to https://paste.example.com.
```

`login` checks the token with the instance before it saves it to
`~/.config/sniptide/config.json`, or `$XDG_CONFIG_HOME/sniptide/config.json`, readable only by
you. `SNIPTIDE_CONFIG` picks another file. A saved token is used only for the exact instance
address it was saved for. `sniptide logout` removes it.

</Tab>
<Tab value="Environment variables">

```bash
export SNIPTIDE_TOKEN='snpt_…'
export SNIPTIDE_BASE_URL='https://paste.example.com'
```

Leave `SNIPTIDE_BASE_URL` unset for the hosted app. It defaults to `https://app.sniptide.com`.

</Tab>
</Tabs>

Environment variables take precedence over saved values, and `--base-url` takes precedence over
the environment. The CLI refuses redirects, so a token never leaves the instance you chose.

## Capture code

```bash
sniptide push src/components/button --title 'Button'
sniptide push 'src/components/**/*.tsx' --title 'Buttons' --collection ui --tag react
sniptide push src/components/Button.tsx --lines 10:35
```

`push` takes files, directories and quoted globs, and combines them. Every pattern must match
something. It prints the new paste's id and how many files it captured.

- A paste holds up to **10 text files** and **1 MiB**. The CLI stops with an error instead of
  dropping files, so narrow larger selections.
- Every file keeps its path relative to the directory you ran `push` in, in sorted order.
- Binary files, symbolic links, `.env` files, Git internals, build and dependency directories,
  and Git-ignored files are left out. Naming one of them explicitly is an error. Use
  [`sniptide env`](#sync-env-files) for `.env` files.
- `--lines START:END` captures part of **one** file, counted from 1 and inclusive. The path and
  range are recorded with the paste.
- Inside a Git repository, the paste records the origin repository, the HEAD commit and whether
  the files differ from it. Credentials in repository URLs are removed.
- `--visibility private|unlisted|public` sets who can open the paste. **The default is private.**
- `--collection` names a collection that already exists. The CLI doesn't create it.
- `--tag` can be repeated, and `--description` adds a description.
- `--dry-run` shows what would be captured without signing in or using the network.

## Restore code

```bash
sniptide pull PASTE_ID --dir src/imported
sniptide pull collection:ui --dry-run
```

`pull` takes a paste id or link, or `collection:<slug>` for a whole collection.

1. It fetches everything and checks every path before it writes anything.
2. It refuses path traversal, symbolic links and duplicate paths across a collection.
3. It creates nested directories and writes the files.

`pull` never replaces an existing file unless you pass `--force`. `--dry-run` lists what it would
write. A collection is restored oldest capture first, up to 1,000 pastes and 20 MiB. Restore into
a fresh directory when you want to review the result on its own.

## Install a collection as an agent skill

```bash
sniptide skill ui
sniptide skill ui --agent cursor --name our-ui --dry-run
```

`skill` turns a collection into a skill that Claude Code, Cursor or Codex loads when a task needs
it. It writes `SKILL.md` with a description and a section for each paste, and puts the files next
to it under `snippets/<paste-slug>/`, so the agent reads only the ones it uses.

| Agent | Option | Folder |
| --- | --- | --- |
| Claude Code | none, the default | `.claude/skills/<name>` |
| Cursor | `--agent cursor` | `.cursor/skills/<name>` |
| Codex | `--agent codex` | `.agents/skills/<name>` |

`--dir` picks another skills folder, and the name defaults to the collection slug. To refresh the
skill after the collection changes, run the command again with `--force`. It replaces the files it
writes and leaves files from removed pastes in place, so delete the skill folder first for an
exact copy. The path checks and size limits of `pull` apply.

## Find pastes

```bash
sniptide search 'button' --language typescript --tag react --limit 20
sniptide list --collection ui --cursor CURSOR
```

`search` finds pastes where every word appears in the title, link, description, tags, a file path
or the code. Both commands return one page. Pass the printed cursor to `--cursor` for the next
one. `--limit` is 1 to 100. Only your own live pastes are listed, without
[encrypted pastes](/core-concepts/encrypted-pastes).

## Sync .env files

Env groups hold a project's environment variables on your instance, encrypted at rest. Edit the
same groups in the [Secrets](/core-concepts/secrets) page of the app.

```bash
sniptide env push my-app              # upload ./.env, replacing the group's variables
sniptide env pull my-app              # write ./.env with mode 0600
sniptide env pull my-app --stdout     # print the variables instead
sniptide env run my-app -- bun dev    # run a command with the variables set
sniptide env list
sniptide env delete my-app
```

- A push **replaces** the whole group, so a variable you removed from the file is removed from the
  group.
- `env pull` writes the group's revision as the file's first line, a comment such as
  `# sniptide env my-app revision 4`. `env push` sends it back, and the push is refused if the
  group changed since, so an old copy of the file can't erase newer variables. Pull again to get
  the changes, or push with `--force` to replace the group anyway. After a push the line is
  updated to the new revision.
- `env pull` won't overwrite an existing file without `--force`.
- `--file PATH` uses a file other than `.env`.
- Values are never printed, even in `--json` output, except by `env pull --stdout`.

Group names are 1 to 64 lowercase letters, digits, `.`, `-` and `_`. A group holds up to 500
variables (32 KB per value, 256 KB in all), and an account up to 100 groups.

## Use the CLI from scripts and agents

Add `--json` (`-j`) and each command writes one JSON object: a success to standard output, or a
failure to standard error with standard output empty.

```json
{"ok":true,"data":{"directory":"/project","files":["src/Button.tsx"],"dryRun":false}}
```

| Exit code | Meaning |
| --- | --- |
| `0` | Success |
| `1` | Configuration, network, server, response or filesystem failure |
| `2` | Invalid input or a path conflict |
| `3` | The token is missing, invalid or lacks the access the command needs |

Requests time out after 30 seconds, and responses are capped at 25 MiB. The CLI never retries a
push, so a flaky connection can't create duplicates. Check `sniptide list` before you push again
after a timeout.

## Move code between machines offline

You don't need an account to hand a capture to another machine:

```bash
sniptide push src/components/button --title 'Button' --output /tmp/button.json
sniptide pull --input /tmp/button.json
```

The bundle is versioned JSON with the code and its source metadata, written readable only by you.
Pulling it never replaces an existing file.

## Command reference

| Command | Purpose | Options |
| --- | --- | --- |
| `sniptide login --token-stdin` | Save a token after checking it | `--base-url` |
| `sniptide logout` | Remove saved credentials | |
| `sniptide push <files\|dirs\|globs>` | Capture up to 10 files | `--title`, `--description`, `--visibility`, `--collection`, `--tag`, `--lines`, `--dry-run`, `--output` |
| `sniptide pull <id\|collection:slug>` | Restore files | `--dir`, `--force`, `--dry-run`, `--input` |
| `sniptide list` | List pastes | `--tag`, `--language`, `--collection`, `--limit`, `--cursor` |
| `sniptide search <query>` | Search pastes | Same as `list` |
| `sniptide skill <collection>` | Install a collection as a skill | `--agent`, `--name`, `--dir`, `--force`, `--dry-run` |
| `sniptide env list` | List env groups | |
| `sniptide env push <group>` | Upload `.env`, replacing the group | `--file`, `--force`, `--dry-run` |
| `sniptide env pull <group>` | Write the group to `.env` | `--file`, `--force`, `--dry-run`, `--stdout` |
| `sniptide env run <group> -- <command>` | Run a command with the group's variables | |
| `sniptide env delete <group>` | Delete an env group | |

Every command also takes `--base-url`, `--json` (`-j`) and `--help` (`-h`). Run
`sniptide --help` for the same summary in the terminal.
