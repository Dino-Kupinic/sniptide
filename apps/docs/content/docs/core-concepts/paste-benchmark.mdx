---
title: Benchmark paste services
description: Measure the time to publish a paste and recover its contents in a separate browser session.
---

The benchmark submits a new single-file paste, opens its share link in a fresh Chrome context with no writer cookies, and checks that the reader can see and recover the complete payload. It prints publish time, read time, end-to-end time and the number of verified round trips for each service.

## Run a comparison

From a checkout of the [Sniptide repository](https://github.com/Dino-Kupinic/sniptide), install Bun, Node.js 24.12 or later, and Google Chrome. Install the locked dependencies with `bun install --frozen-lockfile`.

Create an `instances.json` file for the deployments you want to test. Each entry specifies the editor URL. Where creating pastes requires an account, provide a Playwright storage-state file for a disposable writer account. For example, run `bunx playwright-core codegen --channel chrome --save-storage writer.json http://localhost:3000/new`, sign in, then close the browser. Keep the session file outside version control. If Sniptide serves reader links on a second host, set `readerOrigin` to its origin.

```json
{
  "Sniptide": {"url": "http://localhost:3000/new", "storageState": "writer.json"},
  "PrivateBin": {"url": "http://localhost:8081/"},
  "Opengist": {"url": "http://localhost:6157/", "storageState": "opengist-writer.json"},
  "MicroBin": {"url": "http://localhost:8080/"}
}
```

```sh
bun run benchmark --config instances.json --rounds 8 --bytes 1024
bun run benchmark --config instances.json --rounds 8 --bytes 32768 --json
```

The CLI also recognizes **GitHub Gist**, **Pastebin**, **Hastebin** and **Pastes.io**. An empty options object uses the service's hosted editor. Passing `--hosted` in place of `--config` tries the eight hosted entry points without a writer account. A sign-in prompt, denied request, or unusable share link appears as a failed attempt. Each submission creates a real paste under the instance's retention and visibility settings. Use disposable local storage for repeatable runs and remove it afterward.

## Read the results

- **Publish** runs from invoking the save control until the writer receives a link. Writer sign-in, loading the editor and inserting the payload happen before the timer.
- **Read** runs from opening that link through verifying the contents. Browser rendering and PrivateBin's client-side decryption are included.
- **Round trip** measures both stages on the same paste. Each column reports the median of fully verified samples. The median round trip can differ from the sum of the two stage medians.
- **Verified** counts completed round trips out of all attempts. A failed attempt contributes no latency sample. JSON output records every attempt and its outcome.

Each round uses a new single-line ASCII comment with deterministic hash blocks and a unique round ID. Every provider receives exactly the same bytes within a round. The writer and reader each get a fresh browser context per attempt. Services run sequentially, the starting position rotates each round, and the runner waits 11 seconds before each round to accommodate write rate limits. Use a multiple of the provider count for balanced ordering. Compare local deployments together and hosted deployments together. The results measure an individual user's latency at concurrency one.

## Local results, 20 November 2026

One Apple M1 Pro running macOS 27.2 hosted the browser, four application servers and their storage. Chrome 157.0.8103.80 sent requests over loopback. Sniptide used its production build at commit `044460a` and PostgreSQL 14.20. PrivateBin 2.1.1 used the PHP 8.5.2 built-in server and file storage. Opengist 1.15.3 used SQLite and Git. MicroBin used its 2.1.0 macOS release. Sniptide and Opengist had preauthenticated writers. All readers were signed out.

| Service | Payload | Verified | Publish ms | Read ms | Round trip ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| Sniptide | 1 KiB | 8/8 | 127.5 | 150 | 280 |
| PrivateBin | 1 KiB | 8/8 | 72.5 | 122.5 | 194.5 |
| Opengist | 1 KiB | 8/8 | 611.5 | 124 | 738.5 |
| MicroBin | 1 KiB | 8/8 | 72.5 | 60 | 135.5 |
| Sniptide | 32 KiB | 8/8 | 137.5 | 155 | 297 |
| PrivateBin | 32 KiB | 8/8 | 73.5 | 126 | 200 |
| Opengist | 32 KiB | 8/8 | 618 | 167.5 | 788 |
| MicroBin | 32 KiB | 8/8 | 72 | 72.5 | 145 |

In an earlier 32 KiB series, the first PrivateBin write started four seconds after the previous series, inside its default ten-second rate limit, and the publish timed out. The table uses the complete rerun with an initial cooldown for all four services. [Earlier series](https://github.com/Dino-Kupinic/sniptide/blob/main/docs/benchmarks/paste-roundtrip-32k-pilot-2026-11-20.json). Each service occupied each position twice per size. MicroBin had the lowest median end-to-end time at both sizes on this machine. Most of Opengist's elapsed time was spent publishing. These measurements include browser automation and local application work. Production hosting, network distance, multi-file editing, and concurrent throughput are outside this run.

## Self-hosted Haste community fork, 22 November 2026

The comparison post links to Jakub Jirutka's Haste fork. This follow-up ran its published `haste-server@0.2.1` package on the same Mac, with file storage and anonymous writers and readers. The application served pastes over loopback. Its stock page loads jQuery from Google's CDN, so the reader time includes that external dependency. The four-service series above ran two days earlier. [Fork source and installation](https://github.com/jirutka/haste-server).

| Payload | Verified | Publish ms | Read ms | Round trip ms |
| --- | ---: | ---: | ---: | ---: |
| 1 KiB | 8/8 | 63.5 | 191.5 | 258.5 |
| 32 KiB | 8/8 | 5608 | 1756 | 7385.5 |

[1 KiB samples](https://github.com/Dino-Kupinic/sniptide/blob/main/docs/benchmarks/haste-community-1k-2026-11-22.json) and [32 KiB samples](https://github.com/Dino-Kupinic/sniptide/blob/main/docs/benchmarks/haste-community-32k-2026-11-22.json).

To reproduce, start `haste-server@0.2.1` with its file backend, bind it to loopback and point the CLI's Hastebin adapter at its editor. For example:

```json
{
  "Hastebin": {"url": "http://127.0.0.1:7777/"}
}
```

## Other deployments

Toptal's hosted Hastebin has no measurement in this series. The post lists Pastebin.com and Pastes.io as hosted products. Gists can also run on GitHub Enterprise Server. This run had no Enterprise Server instance. [Blog comparison](https://sniptide.com/blog/pastebin-alternatives) and [GitHub Enterprise Server gist documentation](https://docs.github.com/en/enterprise-server@3.22/get-started/writing-on-github/editing-and-sharing-content-with-gists/creating-gists).
