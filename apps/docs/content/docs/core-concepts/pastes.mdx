A paste is what you share in Sniptide: a title, an optional description and 1 to 10 files, reached
through a link of its own.

## What a paste holds

| Part | Rule |
| --- | --- |
| Title | Required, up to 120 characters. The editor suggests one from the first file. |
| Description | Optional, up to 280 characters. |
| Files | 1 to 10. Each needs a name that is unique within the paste, up to 120 characters. |
| Size | 1 MB for all files together by default. The administrator sets it with `MAX_PASTE_SIZE`. |
| Language | Set from the file name, or detected from the code when the file still has a generated name. Choose **Change language** on a file to set it yourself. |

At least one file must contain code before the paste can be saved.

| Account limit | Default | Set by |
| --- | --- | --- |
| Pastes | 1,000, trash included | `ACCOUNT_PASTE_LIMIT` |
| Storage | 100 MiB of paste content, trash included | `ACCOUNT_STORAGE_BYTES` |
| New pastes | 30 an hour | Fixed |
| Manual edits | 240 an hour | Fixed |
| Auto-saves | 1,800 an hour | Fixed |

**Settings** > **Usage** shows how much of the paste and storage limits you use.

## The link

Every paste has a link, `<domain>/<link>`. By default the link is eight random characters from a
57-character alphabet, giving about 111 trillion possible generated links. Existing links keep
their address when you upgrade.

### Custom links

Set **Custom link** to give a paste a readable address under your username:
`<domain>/@<username>/<name>`, such as `paste.example.com/@ada/deploy-script`. The name is 1 to 40
letters, digits, hyphens or underscores, and each name can be used once under your username. A
custom link needs a username, so set one under **Settings** > **General** first. Your profile
stays at `<domain>/@<username>`, and the pages below a paste follow its link, such as
`paste.example.com/@ada/deploy-script/raw`.

Links made before custom links moved under usernames keep their `<domain>/<link>` address. They
move under your username when you give the paste a new custom link. Custom links that used the
earlier `<domain>/<username>/<name>` form moved to `<domain>/@<username>/<name>`, and the earlier
address no longer opens the paste.

When you change a paste's link, the old link stops working at once. Changing your username moves
all of your custom links to the new username in the same way, so the old addresses stop working
too. The paste keeps its history, collection and view counts, because those belong to the paste
rather than to the link.

Each file is also available as plain text at `<domain>/<link>/raw?file=<file name>`. See
[Raw access](/core-concepts/sharing#raw-access).

## Create and edit a paste

1. Select **New paste**, or press <Kbd>N</Kbd>, to open the editor.
2. Type or paste code. Until you create the paste, the editor keeps your work as a draft on this
   device. Press <Kbd>Ctrl+S</Kbd> (<Kbd>⌘S</Kbd>) to save the draft. If the tab closes before you
   create the paste, opening the editor again restores the draft. Select **Discard** (**Cancel** on
   a phone) to throw the work away, which also deletes the draft.
3. Press <Kbd>Ctrl+Enter</Kbd> (<Kbd>⌘ Enter</Kbd>) to create the paste.

An existing paste saves as you type, and the header shows when it was last saved. Select **Done**
to end the editing session. The next edit then starts a new [revision](/core-concepts/revisions).

When the code looks like a secret, such as an API key or `.env` lines, the editor warns you and
switches a new paste to **Private**, because anyone with the link can read an unlisted paste and
anyone can open a public one. The warning follows the visibility you choose. On a private paste it
reminds you that agents you connected can still read the paste over MCP, and suggests an
[env group](/core-concepts/secrets), which stays encrypted. Turn the warning off with **Secret
detection** under **Settings** > **General**.

To keep the files unreadable to the server, turn on **End-to-end encryption** under
**Protection** before you create the paste. An [encrypted paste](/core-concepts/encrypted-pastes)
can't be edited afterwards.

Pastes you create in the web editor start with the visibility, expiry and burn setting from
[your paste defaults](/settings#set-paste-defaults), which are **Unlisted**, **1 week** and off
until you change them. If you answer that you want a place for your agents to save and share
when you sign up, new pastes never expire, because agents can't read expired pastes.

### Write a paste before you sign in

Without an account you can still open the editor at `/new` and write a paste with every setting
except a custom link and a collection, which stay greyed out until you sign in. The editor keeps the draft on this device. Select
**Sign in to share** and continue with GitHub, Google or email, or create an account. After you
sign in, Sniptide creates the paste with the settings you chose and opens it. If you set a
password, the editor asks you to type it again first, because the draft doesn't store it.

## Start from a template

On Sniptide Cloud, open **Paste templates** from the dashboard or browse the
[template gallery](https://sniptide.com/templates). Choose a template to fill the editor with its
title, description and files. Edit the draft, then create the paste and share it or save it to a
collection. Without an account, [sign in to share](#write-a-paste-before-you-sign-in) it.

### Browse the templates

Select **View all** in the dashboard’s **Paste templates** widget to open the complete gallery.
Filter by category or search by title, description or file name. You can copy the gallery’s
address to share the current filters.

## Find and act on pastes

- **Star** a paste to list it under **Starred**.
- Press <Kbd>⌘K</Kbd> (<Kbd>Ctrl+K</Kbd>), or select **Search** in the tab bar on a phone, to
  search your pastes and your collections by name. A paste matches when every word you type
  appears in its title, link, description, tags, file names or code, the same way agents search
  with `search_snippets`. When the word sits in the code, the result shows the file and the line.
  End-to-end encrypted pastes match on their title and link only, because the server can't read
  their files. Select **New paste named** to start a paste with what you typed as its title.
- The search field in **Pastes** and in a collection matches file names and code the same way.
  **Starred** filters by title and link.
- **Duplicate** copies a paste into a new one that you own.
- In the **Pastes** list, select rows with their checkboxes to star, move, change the visibility
  of or trash several pastes at once. Shift-click selects a range, and `Esc` clears the selection.
  Actions that can be taken back end with an **Undo** button.

## Trash

**Move to trash** removes the paste from every list and stops its link at once. You can
**Restore** it from **Trash** for 30 days. After that it is deleted for good. **Delete forever**
and **Empty trash** remove pastes right away and ask you to confirm first.
[Burned](/core-concepts/burn-after-read) pastes also land in the trash, marked with when they
were read, and come back private when you restore them. A paste that expired keeps its full 30
days once you move it to the trash.

A paste in the trash still counts toward your paste and storage limits until it is deleted.
