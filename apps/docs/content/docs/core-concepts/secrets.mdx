---
title: Encrypted secrets
description: Store a project's environment variables as encrypted Sniptide env groups, reveal values on demand, and share them through expiring password links.
---

**Secrets** holds env groups: a project's environment variables, encrypted before they reach the
database. Edit a group in the app, sync it with [`sniptide env`](/cli#sync-env-files), or read it
through the [SDKs](/sdks). All three work on the same groups.

## Create an env group

1. Open **Secrets** and select **New secret group**.
2. Enter a **Group name**. The CLI uses this name, as in `sniptide env pull my-app`.
3. Optionally set a **Project** and an **Environment** (**Development**, **Staging** or
   **Production**). They group the list on the **Secrets** page.
4. Add variables one at a time, or select **Import .env** to paste a whole file.
5. Select **Save**.

Groups you pushed with the CLI appear here too.

A CLI push replaces the entire group. If you opened the group in the app before someone pushed,
saving fails with "This group changed. Reload before saving again." Reload the page, then make
your change again.

## Reveal and copy values

Values stay masked when the page loads. **Reveal** and **Copy** each send a separate, uncached
request for that value. A revealed value hides again after one minute, when you select **Hide
all**, and when the window loses focus. **Copy** puts the plain value on your system clipboard.

The **Secrets** pages keep no drafts in the browser, don't auto-save and send no analytics events.

## Share a group through a protected link

A group is private until you create a link.

1. In the group, under **Protected sharing**, enter a **Link password** of at least 12 characters.
2. Choose **Expires in**: 1 hour, 1 day or 7 days.
3. Select **Create protected link** and copy the link. It is shown only once.
4. Send the password through a different channel than the link.

The reader opens the link, enters the password and selects **Reveal secrets**. The link shows the
group's **current** values, including edits and CLI pushes made after you created it. Select
**Revoke** to end a link before it expires. **Delete group** deletes every variable and revokes
every link, and the CLI can no longer pull the group.

Sniptide stores only hashes of link tokens and passwords. Every reveal checks the password,
expiry, revocation and request limits. When `SHARE_URL` puts share links on another domain, that
domain must also route `/secret-share/*` to the app.

## How values are encrypted

Values are encrypted with AES-256-GCM using `ENV_SECRETS_KEY`, or a key derived from
`BETTER_AUTH_SECRET` when that isn't set. The server holds the key and can decrypt the values, so
this protects data at rest in the database and its backups. It isn't end-to-end encryption.

Group names, project labels, environment names and variable names are stored unencrypted.

<Callout type="warn">
On a self-hosted instance, keep the encryption key stable and back it up with your database
backups. Changing or losing it makes every stored value unreadable until the groups are pushed
again. See [Configuration](/self-hosting/configuration#pastes-and-sharing).
</Callout>

## Limits

| Limit | Value |
| --- | --- |
| Group name | 1 to 64 lowercase letters, digits, `.`, `-` and `_` |
| Variables per group | 500 |
| Value size | 32 KB per value, 256 KB per group |
| Groups per account | 100 |
