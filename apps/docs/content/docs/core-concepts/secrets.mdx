---
title: Encrypted secrets
description: Store a project's environment variables as encrypted Sniptide env groups, reveal values on demand, give other accounts access, and review every read in the activity log.
---

**Secrets** holds env groups: a project's environment variables, encrypted before they reach the
database. Edit a group in the app, sync it with [`sniptide env`](/cli#sync-env-files), or read it
through the [SDKs](/sdks). All three work on the same groups.

## Create an env group

1. Open **Secrets** and select **New secret group**.
2. Enter a **Group name**. The CLI uses this name, as in `sniptide env pull my-app`.
3. Optionally set a **Project** and an **Environment** (**Development**, **Staging** or
   **Production**). They group the list on the **Secrets** page.
4. Add variables one at a time, or select **Import .env** to paste a whole file.
5. Select **Save**.

Groups you pushed with the CLI appear here too.

A CLI push replaces the entire group. If you opened the group in the app before someone pushed,
saving fails with "This group changed. Reload before saving again." Reload the page, then make
your change again.

## Reveal and copy values

Values stay masked when the page loads. **Reveal** and **Copy** each send a separate, uncached
request for that value. A revealed value hides again after one minute, when you select **Hide
all**, and when the window loses focus. **Copy** puts the plain value on your system clipboard.

The **Secrets** pages keep no drafts in the browser, don't auto-save and send no analytics events.

## Share a group through a protected link

A group is private until you create a link.

1. In the group, under **Protected sharing**, enter a **Link password** of at least 12 characters.
2. Choose **Expires in**: 1 hour, 1 day or 7 days.
3. Select **Create protected link** and copy the link. It is shown only once.
4. Send the password through a different channel than the link.

The reader opens the link, enters the password and selects **Reveal secrets**. The link shows the
group's **current** values, including edits and CLI pushes made after you created it. Select
**Revoke** to end a link before it expires. **Delete group** deletes every variable and revokes
every link, and the CLI can no longer pull the group.

Sniptide stores only hashes of link tokens and passwords. Every reveal checks the password,
expiry, revocation and request limits. When `SHARE_URL` puts share links on another domain, that
domain must also route `/secret-share/*` to the app.

## Give another account access

The owner of a group can give other accounts on the same instance access to it.

1. In the group, under **Access**, enter the person's email or username. Sniptide looks up an
   exact match only.
2. Choose **Can view** or **Can edit**, then select **Add**.

The group appears in the person's **Secrets** list under **Shared with you**.

| Action | Owner | Can edit | Can view |
| --- | --- | --- | --- |
| See variable names, reveal and copy values | Yes | Yes | Yes |
| Add, edit and delete variables | Yes | Yes | No |
| Change the project and environment | Yes | No | No |
| Create and revoke protected links | Yes | No | No |
| Give and remove access | Yes | No | No |
| Read the activity log | Yes | No | No |
| Delete the group | Yes | No | No |

To change someone's access, open the menu next to their name and choose the other level or
**Remove access**. Removing access takes effect on their next request. A person with access can
select **Leave group** to remove their own.

A group can be shared with up to 50 accounts. Shared access works in the app only. The CLI, the
API and the SDKs reach the groups your own account owns.

## Review who read and changed a group

Sniptide records an entry each time a group's values leave the server or its contents and access
change. The owner sees the latest entries under **Activity** in the group and the whole log
through **View all activity**. **Activity** on the **Secrets** page covers every group you own,
including groups you have deleted.

| Entry | Recorded when |
| --- | --- |
| Revealed a variable | Someone reveals or copies a value in the app, or opens it for editing |
| Read every value | An API token or connected agent pulls the group, such as `sniptide env pull` and `env run`, or someone opens a protected link with the right password |
| Created, edited or deleted | The group or its variables change in the app or through a token. The entry names the variables, never their values |
| Protected link created or revoked | The owner creates or revokes a link |
| Access given, removed or left | The owner changes someone's access, or a person leaves |

Each entry shows the account that acted, whether the request came from the app, a named API token
or a protected link, and the time in UTC. A protected link needs no account, so its entry names
no one. Failed link passwords and the list of group names aren't recorded.

Entries can't be edited or deleted, in the app or through the API. The database refuses updates
to the log and removes a log only when its owner's account is deleted. Sniptide doesn't record
IP addresses in the log.

## How values are encrypted

Values are encrypted with AES-256-GCM using a key derived from `ENV_SECRETS_KEY` if set, or
`BETTER_AUTH_SECRET` otherwise. The server holds the key and can decrypt the values, so
this protects data at rest in the database and its backups. It isn't end-to-end encryption.

Group names, project labels, environment names and variable names are stored unencrypted.

<Callout type="warn">
On a self-hosted instance, keep the encryption key stable and back it up with your database
backups. Changing or losing it makes every stored value unreadable until the groups are pushed
again. See [Rotate the auth secret](/self-hosting/configuration#rotate-the-auth-secret).
</Callout>

## Limits

| Limit | Value |
| --- | --- |
| Group name | 1 to 64 lowercase letters, digits, `.`, `-` and `_` |
| Variables per group | 500 |
| Value size | 32 KB per value, 256 KB per group |
| Groups per account | 100 |
| Accounts a group is shared with | 50 |
