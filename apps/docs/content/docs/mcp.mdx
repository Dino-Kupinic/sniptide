The Sniptide MCP server lets a coding agent search your snippets, read them, fetch a collection
as ordered steps and, if you allow it, save and edit snippets. It runs inside the app at
`/api/mcp`, on the hosted app and on every self-hosted instance, so there is no separate service
to deploy.

## Install in your agent

Claude Code and Gemini CLI can install Sniptide as a plugin, which adds the MCP server and the
five Sniptide skills in one step. The plugin connects to the hosted app at
`https://app.sniptide.com`, and the client signs you in through [OAuth](/oauth) the first time
it calls Sniptide. For a self-hosted instance or another client, use
[Connect an agent](#connect-an-agent) instead.

<Tabs items={["Claude Code", "Gemini CLI"]} groupId="agent" persist>
<Tab value="Claude Code">

Add the Sniptide marketplace, then install the plugin from it:

```bash
claude plugin marketplace add Dino-Kupinic/sniptide
claude plugin install sniptide@sniptide
```

Start Claude Code, type `/mcp`, choose `sniptide` and pick **Authenticate**.

</Tab>
<Tab value="Gemini CLI">

```bash
gemini extensions install https://github.com/Dino-Kupinic/sniptide
```

Start Gemini CLI and run `/mcp auth sniptide` to sign in.

</Tab>
</Tabs>

The extension and plugin manifests contain no token. To check the install, ask the agent to list
your Sniptide collections.

## Connect an agent

Run the command for your client. The client opens Sniptide in your browser, where you allow
access. On a self-hosted instance, replace `https://app.sniptide.com` with your instance's
address.

<Tabs items={["Claude Code", "Codex", "Cursor"]} groupId="agent" persist>
<Tab value="Claude Code">

```bash
claude mcp add --transport http sniptide https://app.sniptide.com/api/mcp
```

Then start Claude Code, type `/mcp`, choose `sniptide` and pick **Authenticate**. Adding the server
doesn't open the browser on its own.

</Tab>
<Tab value="Codex">

```bash
codex mcp add sniptide --url https://app.sniptide.com/api/mcp
```

</Tab>
<Tab value="Cursor">

Add a remote MCP server with the URL `https://app.sniptide.com/api/mcp` and no headers, or use
**Add to Cursor** in the app's welcome setup or on the dashboard.

</Tab>
</Tabs>

The dashboard shows the same commands with your instance's address filled in, until an agent
connects. After that it lists each connected agent and when it last called Sniptide, to the
minute. Select **Connect another agent** below the list to see the setup again, and
**Manage in Settings** to revoke one. The setup lives in the dashboard's Agents
widget, and the close button removes that widget from your
[dashboard layout](/getting-started/dashboard).

To check the connection, ask the agent to list your Sniptide collections. It calls
`list_collections` and answers with your collections, or with an empty list on a new account.
[OAuth for agents](/oauth) explains the sign-in, its scopes and how to revoke a connection.

### Connect with an API token instead

Use a [personal API token](/api-tokens) when the client doesn't support OAuth, or for an
unattended agent. Choose a **read-only** token if the agent should only look things up, and turn
on **Write access** only if it should save and edit snippets.

<Tabs items={["Claude Code", "Cursor"]} groupId="agent" persist>
<Tab value="Claude Code">

Put this in the project's `.mcp.json`, and export `SNIPTIDE_TOKEN` before you start Claude Code,
which expands `${SNIPTIDE_TOKEN}`:

```json title=".mcp.json"
{
  "mcpServers": {
    "sniptide": {
      "type": "http",
      "url": "https://app.sniptide.com/api/mcp",
      "headers": { "Authorization": "Bearer ${SNIPTIDE_TOKEN}" }
    }
  }
}
```

</Tab>
<Tab value="Cursor">

Put this in your private `~/.cursor/mcp.json`, or in a project `.cursor/mcp.json` that Git
ignores, and replace the placeholder with your token:

```json title="~/.cursor/mcp.json"
{
  "mcpServers": {
    "sniptide": {
      "url": "https://app.sniptide.com/api/mcp",
      "headers": { "Authorization": "Bearer YOUR_PERSONAL_API_TOKEN" }
    }
  }
}
```

</Tab>
</Tabs>

Keep real tokens out of source control. Connect with **Streamable HTTP**, not the older SSE
transport. Every request is authenticated again, so revoking a token or a connection cuts off
access at once.

### Run the server locally

The `@sniptide/mcp` package runs the same tools as a local stdio process that calls the token API.
Use it when your client only supports stdio servers. It needs Node.js 24 or newer and an API
token.

```json title=".mcp.json"
{
  "mcpServers": {
    "sniptide": {
      "type": "stdio",
      "command": "npx",
      "args": ["--yes", "@sniptide/mcp"],
      "env": {
        "SNIPTIDE_TOKEN": "${SNIPTIDE_TOKEN}",
        "SNIPTIDE_BASE_URL": "https://app.sniptide.com"
      }
    }
  }
}
```

Cursor uses the same `command`, `args` and `env` fields without `type`. Keep the token in
private configuration. The local server reads only `SNIPTIDE_TOKEN` and `SNIPTIDE_BASE_URL`, not
the CLI's saved credentials. It requires HTTPS except on `localhost` and refuses redirects.

Contributors can build it from a checkout with `bun install && bun --filter @sniptide/mcp build`,
then run `node` with the absolute path to `packages/mcp/dist/sniptide-mcp.js`.

## Tools

| Tool | What it does | Access |
| --- | --- | --- |
| `search_snippets` | Returns a page of summaries. `query` matches when every word appears in the title, description, tags, file paths or code. Filters by tags, language and collection. `nextCursor` continues the search. | read |
| `read_snippet` | Returns one snippet by id or link, with its file paths, code and source metadata. | read |
| `list_collections` | Lists your collections with their slugs, names and how many live snippets each holds. | read |
| `fetch_collection` | Returns a page of a collection as numbered steps with the full snippets, oldest capture first. | read |
| `create_snippet` | Saves a new snippet. It is private unless `visibility` is set. | write |
| `update_snippet` | Replaces a snippet's title and **all** its files. Marked destructive. | write |
| `update_snippet_settings` | Changes visibility, expiry, password or burn after read. Marked destructive. The password is never returned. | write |
| `create_collection` | Creates an empty collection by name and returns its slug. | write |
| `trash_snippet` | Moves a snippet to the trash, where you can restore it in the app. Marked destructive. Nothing is deleted for good. | write |

The agent only reaches the account owner's **own** live snippets, private ones included. It can't
reach other people's snippets, snippets shared with you, the trash or expired snippets. The
server doesn't run code, write files to your machine, expose env groups or accept browser
sessions. Changing a link, renaming or deleting collections, restoring from the trash and
inviting people stay in the app.

## Prompts

The server offers three prompts, which Claude Code and Cursor list in their slash menus. Each one
starts a common job with the right tools in the right order.

| Prompt | Arguments | What it asks the agent to do |
| --- | --- | --- |
| `use_snippet` | `task` | Search your snippets for the task, read the best match and adapt it to the project. |
| `save_snippet` | `code`, optional `collection` | Propose a title, tags and paths, leave secrets out, and save a private snippet after you confirm. |
| `apply_collection` | `collection`, optional `goal` | Fetch every page of the collection, list its steps and wait for your go-ahead before applying them in order. |

The `collection` argument completes from your collection slugs. To give an agent a collection
without the MCP server, install it as a skill with [`sniptide skill`](/cli#install-a-collection-as-an-agent-skill).

## Work with snippets

Ask in plain language once Sniptide is enabled in the client:

> Search my Sniptide snippets for a TypeScript button tagged react, read the best match, and adapt
> it to this project's conventions. Then fetch my ui collection and apply its steps in order.

A well-behaved agent searches the summaries first and reads only the snippet it needs.

- **Collections.** A `fetch_collection` page holds up to 50 snippets. To continue, the agent
  passes `nextCursor` and `nextStep` back as `cursor` and `startStep`. Steps come oldest capture
  first, the same order the [CLI](/cli) uses.
- **Saving.** `create_snippet` takes a title and the complete `files` list, and optionally tags,
  source metadata and the slug of an existing collection. The snippet is created private.
- **Editing.** An update replaces every file, so the agent should read the snippet first and send
  every file it wants to keep. Fields it leaves out (description, visibility, collection, tags
  and source) keep their values. `null` clears a collection or source, and `[]` clears tags.
- **Sharing settings.** `update_snippet_settings` changes visibility, expiry (counted from now),
  password and burn after read. A password set this way appears in the conversation, so the agent
  should ask you first.

Creates and edits are never retried automatically. The client decides whether to ask you before
it writes.

<Callout type="warn">
Treat snippet content as data from whoever wrote it. The server tells clients to read it as code
and to follow only your instructions. Give an agent write access only when it needs it, and
review what it saves.
</Callout>

## Install the agent plugin

The Sniptide repository is also an [Agent Plugin](https://agent-plugins.org). `plugin.json`
bundles the MCP servers in `mcp.json` with five skills: `setup-sniptide`, `reuse-snippets`, `save-snippets`,
`apply-collection` and `integrate-sniptide-sdk`. The plugin's MCP configuration sends
`SNIPTIDE_TOKEN` as a bearer token, so export a token before you use it. How you install a plugin
depends on your client.

The same repository carries a Claude Code plugin in `.claude-plugin/` and a Gemini CLI extension
in `gemini-extension.json`. Both bundle the same five skills, connect through OAuth instead of a
token, and install with the commands in [Install in your agent](#install-in-your-agent).

## Limits and errors

- An agent never sees an [encrypted paste](/core-concepts/encrypted-pastes). The tools don't
  list, read or change one.
- MCP requests share the token's **3,600 requests an hour**, the limit of 30 new pastes an hour,
  paste validation and the account's storage limit.
- Request bodies are capped at 8 MiB and tool results at 25 MiB. Read single snippets if a
  collection page is too large.
- Each `read_snippet` call and each snippet in a `fetch_collection` page counts as a read. The
  snippet's page shows its owner how many times it was read through MCP or the CLI, apart from its
  views. Searches and the read-back after a write don't count.

| Response | Meaning | Action |
| --- | --- | --- |
| `401` | The token or connection is missing, expired, invalid or revoked. | Sign in again, or replace the token. |
| Tool error "doesn't have the write scope" | The token or connection is read-only. | Connect again with `write`, or use a token with **Write access**. |
| `403` | The request came from a browser origin other than the app's. | Call the server from the agent, not from a web page. |
| `405` | A plain `GET` or `DELETE` reached the endpoint. The server is stateless and has no sessions. | Connect with Streamable HTTP. |
| `429` | A rate limit was reached. | Wait for `Retry-After` before retrying. |
