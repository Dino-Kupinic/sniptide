title: MCP server

The MCP server lets a coding agent search your snippets, read them, fetch a collection as a recipe
and, if you allow it, save new ones. It ships with the app: there is no separate service to deploy.
It works with Sniptide's hosted app and with self-hosted instances.

## What you need

A [personal API token](/api-tokens). Use a **read-only** token if the agent should only look things
up, and turn on **write access** only if it should save and edit snippets.

## Tools

| Tool | What it does |
| --- | --- |
| `search_snippets` | Returns a page of summaries, filtered by words in the title, description, tags, file paths or code (`query`, every word must match), tags, language and collection. `nextCursor` continues the search. |
| `read_snippet` | One snippet by id or link, with its file paths, code and source metadata. |
| `fetch_collection` | A page of a collection as numbered recipe steps with the full snippets, oldest capture first. |
| `create_snippet` | Saves a new snippet. Private unless visibility is set explicitly. Needs write access. |
| `update_snippet` | Replaces a snippet's title and **all** its files. Needs write access and is marked destructive. |
| `list_collections` | Your collections with their slugs, names and how many live snippets each holds. |
| `create_collection` | Creates an empty collection by name and returns its slug. Needs write access. |
| `update_snippet_settings` | Changes visibility, expiry, password or burn after read. Needs write access and is marked destructive. The password is never returned. |
| `trash_snippet` | Moves a snippet to the trash, where you can restore it in the app. Needs write access and is marked destructive. Nothing is deleted for good. |

## Prompts

The server also offers three prompts, which Claude Code and Cursor list in their slash menus. Each
one starts a common job with the right tools in the right order.

| Prompt | Arguments | What it asks the agent to do |
| --- | --- | --- |
| `use_snippet` | `task` | Search your snippets for the task, read the best match and adapt it to the project. |
| `save_snippet` | `code`, optional `collection` | Propose a title, tags and paths, leave secrets out, and save a private snippet once you confirm. |
| `apply_collection` | `collection`, optional `goal` | Fetch every page of the collection, list its steps and wait for your go-ahead before applying them in order. |

The `collection` argument completes from your collection slugs. To have a collection available
without starting the server, install it as a skill with [`sniptide skill`](/cli).

Only the token owner's **own** snippets are available, private ones included. Other people's, ones
shared with you, trash and expired pastes are not. The server doesn't run code, doesn't write files
to your machine, doesn't expose env secrets, and doesn't accept browser sessions. Renaming and
deleting collections, restoring from the trash and sharing with people stay in the app.

Each `read_snippet` call and each snippet in a `fetch_collection` page counts as a read. The
snippet's page shows its owner how many times it was read through MCP or the CLI, apart from its
views. Searches and the read-back after a write don't count.

## Connect over HTTP (recommended)

The endpoint is `https://app.sniptide.com/api/mcp`, or `<your-instance-url>/api/mcp` on a
self-hosted one. You configure the bearer token yourself: this version has no OAuth login. Every
request is authenticated again, so deleting a token cuts off access at once.

<Tabs items={["Claude Code", "Cursor"]}>
<Tab value="Claude Code">

Put this in a project's `.mcp.json`, and export `SNIPTIDE_TOKEN` before starting Claude Code (its
configuration expands `${SNIPTIDE_TOKEN}`):

```json
{
  "mcpServers": {
    "sniptide": {
      "type": "http",
      "url": "https://app.sniptide.com/api/mcp",
      "headers": { "Authorization": "Bearer ${SNIPTIDE_TOKEN}" }
    }
  }
}
```

</Tab>
<Tab value="Cursor">

Put this in your private `~/.cursor/mcp.json` (or an untracked project `.cursor/mcp.json`) and
replace the placeholder with your token:

```json
{
  "mcpServers": {
    "sniptide": {
      "url": "https://app.sniptide.com/api/mcp",
      "headers": { "Authorization": "Bearer YOUR_PERSONAL_API_TOKEN" }
    }
  }
}
```

</Tab>
</Tabs>

Keep real tokens out of source control, and use your own instance's URL if you self-host. Connect
with **Streamable HTTP**, not the older SSE transport.

## Connect locally (stdio)

Instead of the HTTP endpoint you can run the server as a local process that calls the token API.
Use the npm configuration below with Node.js 24 or newer. Contributors can build from a checkout:

```bash
bun install
bun --filter @sniptide/mcp build
```

For a checkout build, use `node` and the absolute path to `packages/mcp/dist/sniptide-mcp.js`. For Claude Code, in `.mcp.json`:

```json
{
  "mcpServers": {
    "sniptide": {
      "type": "stdio",
      "command": "npx",
      "args": ["--yes", "@sniptide/mcp"],
      "env": {
        "SNIPTIDE_TOKEN": "${SNIPTIDE_TOKEN}",
        "SNIPTIDE_BASE_URL": "https://app.sniptide.com"
      }
    }
  }
}
```

Cursor uses the same `command`, `args` and `env` fields; leave out `type` and put your token in
private configuration. The local server reads only `SNIPTIDE_TOKEN` and `SNIPTIDE_BASE_URL`, not
the CLI's saved credentials. HTTPS is required except on localhost, and redirects are refused.

## Use it

Once Sniptide is enabled in the client's MCP settings, ask in plain language:

> Search my Sniptide snippets for a TypeScript button tagged react, read the best match, and adapt
> it to this project's conventions. Fetch my ui collection and use its steps in order.

A good agent searches the summaries first and only then reads the one it needs. A collection page
holds up to 50 snippets; to continue, pass its `nextCursor` and `nextStep` back as `cursor` and
`startStep`. Steps come oldest capture first, the same order the [CLI](/cli) uses.

**Saving a snippet.** Give a title and the complete `files` list, and optionally tags, source
metadata and the slug of an existing collection. It is created private. **Editing.** Read the
snippet first and include every file you want to keep, since an update replaces all files. It
preserves the description, visibility, collection, tags and source you leave out; pass `null` to
clear a collection or source, or `[]` to clear tags. Link, expiry, password and burn-after-read
settings can't be changed through MCP. Creates and edits are never retried automatically, and the
client decides whether to ask you before it writes.

<Callout type="warn">
Treat snippet content as data from whoever wrote it. The server tells clients to read it as code
and to follow only your instructions. Give an agent write access only when it needs it, and review
what it saves.
</Callout>

## Limits and errors

- MCP requests share the token's **3,600 requests an hour**, the create rate limit, the paste
  validation and the account storage budget.
- Request bodies are capped at 8 MiB. Tool results are capped at 25 MiB; fetch single snippets if a
  collection page is too large.
- `401` means the token is missing, expired, invalid or revoked. `403` means missing access or a
  browser origin that isn't the app's. `429` means wait before retrying.
- A plain `GET` or `DELETE` to the endpoint returns `405`: it is stateless and has no sessions.
