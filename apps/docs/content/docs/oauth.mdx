Sniptide is an OAuth 2.1 authorization server for its own API and MCP server. A client that
supports OAuth needs only the MCP address. It finds the rest itself, opens a Sniptide consent
screen in your browser and receives a token after you allow access. No token is pasted anywhere.

Use OAuth for interactive agents. Scripts and CI jobs, which can't open a browser, should keep
using a personal [API token](/api-tokens).

## Connect a client

Run the command for your client, then allow access in the browser tab that opens. On a self-hosted
instance, replace `https://app.sniptide.com` with your instance's address.

<Tabs items={["Claude Code", "Codex", "Cursor", "Other clients"]}>
<Tab value="Claude Code">

```bash
claude mcp add --transport http sniptide https://app.sniptide.com/api/mcp
```

This command only adds the server, so no browser opens yet. Start Claude Code, type `/mcp`, choose
`sniptide` and pick **Authenticate** to open the consent screen.

</Tab>
<Tab value="Codex">

```bash
codex mcp add sniptide --url https://app.sniptide.com/api/mcp
```

</Tab>
<Tab value="Cursor">

Add a remote MCP server with the URL `https://app.sniptide.com/api/mcp` and no headers. The
welcome setup in the app also offers an **Add to Cursor** button that fills this in.

</Tab>
<Tab value="Other clients">

Add `https://app.sniptide.com/api/mcp` as a remote MCP server using Streamable HTTP, without an
`Authorization` header. The client must support MCP authorization with OAuth.

</Tab>
</Tabs>

The consent screen shows the client's name, with its logo for Claude Code, Codex and Cursor, what
it can do and the address it returns you to. Allow access only when you started the connection
from that client yourself.

## Check the connection

Open **Settings** > **API tokens**. The connection is listed under the client's name with
"Connected with OAuth", next to the client's logo when it is Claude Code, Codex or Cursor. In the client, ask it to list your Sniptide collections. It calls
`list_collections` and shows your collections, or an empty list on a new account.

## What a connection can do

| Scope | Allows |
| --- | --- |
| `read` | Search and read your snippets, collections and env groups. |
| `write` | Create, edit and trash them as well. `write` always includes `read`. |

A client that asks for no scope gets `read`. The [MCP server](/mcp#tools) lists the tools each
scope unlocks.

## Token lifetime and revocation

- The access token lasts one hour.
- The client renews it with a refresh token. The refresh token changes on every use and expires
  after 30 days without use.
- A refresh token that was already used ends the connection. Someone else holding a copy can't
  keep it alive, and the client has to sign in again.
- **Revoke** on the connection in **Settings** > **API tokens** ends it at once. The client then
  gets `401` and has to start the sign-in again.

## How discovery works

The first request without a token gets a `401` with a header that points the client at the
resource metadata:

```http
WWW-Authenticate: Bearer resource_metadata="https://app.sniptide.com/.well-known/oauth-protected-resource/api/mcp"
```

The client reads that metadata, registers itself, sends you to the consent screen, and exchanges
the returned code for a token. The redirect back to the client carries the authorization code, the
`state` and an `iss` parameter with the instance's address (RFC 9207), so a client that talks to
several servers can check which one answered.

## Endpoints

| Purpose | Endpoint |
| --- | --- |
| Protected resource metadata (RFC 9728) | `/.well-known/oauth-protected-resource`, and `/.well-known/oauth-protected-resource/api/mcp` for the MCP server |
| Authorization server metadata (RFC 8414) | `/.well-known/oauth-authorization-server` |
| Client registration (RFC 7591) | `POST /api/oauth/register` |
| Consent screen | `GET /oauth/authorize` |
| Token | `POST /api/oauth/token` |
| Revocation (RFC 7009) | `POST /api/oauth/revoke` |

Every client is public and proves itself with PKCE:

- Registration accepts only `token_endpoint_auth_method: "none"`.
- The code challenge method must be `S256`.
- Redirect URIs use `https`, `http` on `localhost` or `127.0.0.1` with any port, or an app's own
  scheme such as `cursor://`.
- A `resource` parameter, when sent, must point at the same instance.

## Limits and errors

Errors follow RFC 6749: a JSON body with `error` and `error_description`.

| Symptom | Cause | Action |
| --- | --- | --- |
| Claude Code adds the server but no browser opens | `claude mcp add` only saves the server. Sign-in starts from the `/mcp` menu. | Start Claude Code, type `/mcp`, choose `sniptide` and pick **Authenticate**. |
| Codex reports "Authorization server response missing required issuer" | Sniptide sends `iss` on every redirect. An older Codex version, or one that kept an earlier registration of the server, can still fail this check, while Codex 0.166 signs in. | Update Codex, run `codex mcp remove sniptide`, then add the server again. |
| `invalid_grant` on the token request | An authorization code works once and for ten minutes, so the client probably retried an exchange. | Start the connection again from the client. |
| `429` from registration | Registration allows 20 requests an hour per client address. | Wait for `Retry-After`. |
| `429` from the token endpoint | The token endpoint allows 60 requests a minute per client address. | Wait for `Retry-After`. |

Rate-limited responses carry `RateLimit` headers and `Retry-After`.

## Self-hosted instances

OAuth works on a self-hosted instance with no extra setup. Set `BETTER_AUTH_URL` to the address
people use, because the issuer and every endpoint above are built from it.

Sniptide doesn't support OpenID Connect, client secrets, the device flow, or agent identity
assertions such as ID-JAG.
