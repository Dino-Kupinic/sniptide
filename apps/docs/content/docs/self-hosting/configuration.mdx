title: Configuration
description: Look up every environment variable a self-hosted Sniptide instance reads, with its default, allowed values and effect.
---

Sniptide reads its configuration from environment variables when the server starts. They aren't
built into the image, so a change takes effect when you restart the container, for example with
`docker compose up -d`. The server checks every value at startup and stops with the variable's
name when one is invalid, instead of falling back to a default. A variable that is set but empty
counts as unset.

The repository's `apps/web/.env.example` lists the app settings. The Docker Compose and Coolify
templates pass selected variables through to the container. See
[Docker Compose](/self-hosting/docker-compose#pass-through-an-extra-app-setting) or
[Coolify](/self-hosting/coolify#change-settings) to add a setting the template doesn't list.

## Required

| Variable | Default | What it does |
| --- | --- | --- |
| `DATABASE_URL` | none | Postgres connection string, `postgres://user:password@host:5432/sniptide`. Sniptide tests Postgres 17 and 18. Compose runs Postgres 17 and sets this for you. |
| `BETTER_AUTH_SECRET` | none | Signs sessions and supplies the default key for env group values. Generate with `openssl rand -hex 32` and keep it across restarts. Changing it signs everyone out. See [Rotate the auth secret](#rotate-the-auth-secret) if you store env groups. |
| `BETTER_AUTH_URL` | none | The exact URL people open in the browser (`https://…` behind a proxy). The app boots without it, but sign-in and sign-up are rejected from any other origin ("Invalid origin"), and OAuth callbacks and printed links use it. |

## Sign-in and sign-up

| Variable | Default | What it does |
| --- | --- | --- |
| `ALLOW_SIGN_UP` | `true` | `false` closes sign-up for everyone, and `first` closes it once the first account exists. Existing accounts keep signing in. It wins over `ALLOWED_EMAILS`. The install script and the Coolify template set `first`. |
| `ALLOWED_EMAILS` | unset | Comma-separated emails that may sign up (invite-only). New password accounts need SMTP email verification before signing in; without SMTP, only verified OAuth identities can join. Existing accounts keep signing in. |
| `HOME_URL` | unset | The logo on the sign-in screens links here, for example to your landing page. Unset, the logo is not a link. |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | unset | Turn on GitHub sign-in. Until both are set the button shows as disabled. Callback URL: `<BETTER_AUTH_URL>/api/auth/callback/github`. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | unset | Turn on Google sign-in. Callback URL: `<BETTER_AUTH_URL>/api/auth/callback/google`. |
| `BETTER_AUTH_TRUSTED_ORIGINS` | unset | Extra origins allowed to call the auth API, comma-separated, besides `BETTER_AUTH_URL`. |
| `COOKIE_DOMAIN` | unset | Share the session cookie with other subdomains. Leave unset on one domain. |
| `COOKIE_PREFIX` | `better-auth` | Prefix for the auth cookies' names (letters, digits, `-`, `_`). Set a different one on a deployment that shares a parent domain with another one (a preview next to production). Changing it signs everyone out. |
| `DEMO_MODE` | `false` | A public demo: every visitor is signed in to one shared guest account with example data, reset on a schedule. The workspace uses the regular app layout without a demo banner. The welcome paste explains the shared account and resets. Pastes made in the demo are visible to every visitor and deleted at the next reset. Use it with `ALLOW_SIGN_UP=false` so the guest is the only account. |
| `DEMO_RESET_MINUTES` | `60` | With `DEMO_MODE`, minutes between resets (5 to 1440). The guest is also reset at server start. |

Existing email and password accounts keep signing in. Pending invitations remain blocked until
their email is verified, even if the invite list or SMTP is later disabled. See also
[closing sign-up](/getting-started/self-hosted#close-sign-up-for-a-private-instance).

GitHub and Google sign-in require your own OAuth app credentials and the callback URLs listed
above.

## Links and legal pages

| Variable | Default | What it does |
| --- | --- | --- |
| `HOMEPAGE_URL`, `DOCS_URL`, `HELP_URL` | The Sniptide project's site, docs and issue tracker | Where the **Homepage**, **Documentation** and **Help** links under **Resources** in the account menu go. They open in a new tab. |
| `TERMS_URL`, `PRIVACY_URL` | unset | Turn "Terms" and "Privacy Policy" under the sign-in and sign-up forms into links. Without them that line is left out. |
| `OPERATOR_NAME`, `OPERATOR_ADDRESS` | unset | Sign the foot of every email with who sends it and a postal address. |
| `COPYRIGHT_EMAIL` | unset | Publishes `/copyright`, which explains how to send a copyright takedown notice or counter-notice to this address, with `OPERATOR_NAME` and `OPERATOR_ADDRESS` as the agent. |

A private server can leave all of these unset.

## Pastes and sharing

| Variable | Default | What it does |
| --- | --- | --- |
| `MAX_PASTE_SIZE` | `1MB` | The most one paste can hold, across its files. Plain bytes or a number with a unit (`B`, `KB`, `MB`, `GB`, binary: 1 KB = 1024 bytes): `1MB`, `512KB`, `1.5MB` and `1048576` all work. |
| `SHARE_URL` | unset | Domain share links use when it differs from the app's. Leave unset to serve everything on one domain. |
| `SHARE_PROXY_SECRET` | unset | Shared with a separate share-domain site that proxies share pages to the app, so it can pass the visitor's IP. |
| `GITHUB_TOKEN` | unset | A GitHub token (no scopes needed) for gist imports. Without it the server shares GitHub's unauthenticated quota of 60 requests an hour. |
| `SLACK_WEBHOOK_URL`, `DISCORD_WEBHOOK_URL` | unset | Incoming webhooks that **Share via…** posts paste links to. One channel per provider. Every paste owner on the instance can post to it, 20 times an hour per account. Keep the URLs secret. |
| `ENV_SECRETS_KEY` | unset | Secret of at least 32 characters from which Sniptide derives the encryption key for env group values. When unset, Sniptide derives the key from `BETTER_AUTH_SECRET`. |

### Rotate the auth secret

Keep the secret that protects your existing env groups. If `ENV_SECRETS_KEY` is already set, keep
its current value when you change `BETTER_AUTH_SECRET`. If it is unset and the old auth secret is
still safe to keep, set `ENV_SECRETS_KEY` to the **exact old value** of `BETTER_AUTH_SECRET`
(at least 32 characters) and set the new `BETTER_AUTH_SECRET` in the same deployment. After
restarting, sign in again and check that an existing env group can still be read.

To retire the old encryption secret, have each group owner save a secure copy of their values
before changing the key, for example with [the CLI](/cli#sync-env-files). After deploying the
new key, push the saved groups again and verify that their values can be read. A database dump
contains encrypted values, so keep the original secret with any backups taken before the change.

### Separate share domain

To serve share links on their own domain, such as `paste.example` next to `app.paste.example`:

1. Point the share domain at the same container as the app.
2. Set `SHARE_URL` to the share domain's HTTPS address and restart the app.
3. If another site proxies the share domain, route `/secret-share/*` to the app as well as paste
   links.

Copied links then use the share domain. Share pages and raw files stay on it, and app pages
opened there redirect to `BETTER_AUTH_URL`. Open a copied link to check that it loads the paste.

## Email

Notification emails are off until you configure SMTP. In-app notifications and password sign-in
work without it. Set the host, port and sender together, plus `BETTER_AUTH_URL` and a
`BETTER_AUTH_SECRET` of at least 32 characters. Users verify their address and opt in per event in
**Settings** > **Notifications**.

The same SMTP settings enable password reset emails. Without SMTP, the forgot-password page asks
people to contact the administrator.

Every email goes out as HTML with a plain-text version that carries the same sentences and links.
The HTML follows the reader's light or dark appearance in clients that support it, such as Apple
Mail. Gmail and Outlook on the web apply their own dark mode instead. The only images are the
Sniptide logo, which email clients load from `<BETTER_AUTH_URL>/email/`, so that address must be
reachable from the internet for the logo to show. Clients that block images show the name instead.

Emails are written in the reader's language: English, German, Spanish, Japanese or Simplified
Chinese. Account emails, such as a password reset, use the language of the browser that asked for
them. Notification emails use the language the person last picked in Sniptide, or the one they were
using when they turned on an email, and English before either happens.

| Variable | Default | What it does |
| --- | --- | --- |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM` | unset | Server, port and sender address. All three are needed. |
| `SMTP_USER`, `SMTP_PASSWORD` | unset | Credentials; supply both or neither. |
| `SMTP_SECURE` | `false` | `true` for implicit TLS (port 465). |
| `SMTP_REQUIRE_TLS` | `true` | Require STARTTLS otherwise. Only set `false` for a trusted local test server. |
| `NOTIFICATION_EMAIL_CONCURRENCY` | `2` | How many notification emails are sent at once, 1 to 10. |

### Email delivery

Email runs independently once a minute and uses a durable queue with bounded retries. Events older
than 24 hours are skipped, including events queued while SMTP was unavailable. Delivery rechecks
consent and access, and messages contain generic activity text with links to the signed-in app.
Each email includes a confirmation link that stops only that event's emails. Opening it does not
change preferences. Email is delivered at least once when retries succeed; a crash after SMTP
acceptance and before recording success can cause a duplicate. A concurrent access change can
still allow an already sending generic email to arrive.

## Client IP

| Variable | Default | What it does |
| --- | --- | --- |
| `CLIENT_IP_SOURCE` | `direct` | Where rate limits get the visitor's IP: `direct`, `x-forwarded-for`, `x-real-ip` or `cloudflare`. |
| `TRUSTED_PROXIES` | unset | With `x-forwarded-for`: the proxies' addresses or ranges (`private` covers loopback and Docker's private ranges). |
| `TRUSTED_PROXY_HOPS` | `1` | With `x-forwarded-for` and no list: how many proxies append to the header. |

Pick these to match what sits in front of the app: see [Reverse proxy and client IP](/self-hosting/reverse-proxy).

## Database and capacity

Each process uses its configured pool and can open one dedicated live-update listener. Budget for
replicas × (pool size + 1), plus migration and admin connections, within Postgres' connection limit.
Invalid values stop the server with the allowed range.

| Variable | Default | Range | What it does |
| --- | --- | --- | --- |
| `DATABASE_POOL_SIZE` | `10` | 1 to 100 | Connections per process. |
| `HTTP_ADMISSION_LIMIT` | `64` | 1 to 1024 | Active ordinary dynamic requests per process. Excess requests receive 503. |
| `PROBE_ADMISSION_LIMIT` | `2` | 1 to 16 | Active health and metrics requests. |
| `LIVE_ADMISSION_LIMIT` | `128` | 1 to 4096 | Active live-update streams, separate from ordinary requests. |
| `DATABASE_PROBE_RESERVE` | `1` | 1 to 16 | Reserved database execution capacity for probes. |
| `DATABASE_MAINTENANCE_RESERVE` | `1` | 1 to 16 | Reserved database execution capacity for background jobs. |
| `DATABASE_ADMISSION_QUEUE_LIMIT` | `64` | 0 to 4096 | Maximum waiting database submissions per process. |
| `VISIT_DRAIN_BATCH_SIZE` | `500` | 1 to 5000 | Maximum ordinary visits applied per drain batch. |
| `VISIT_QUEUE_MAX_LAG_MS` | `30000` | 1000 to 3600000 | Pending-visit age that triggers temporary backpressure. |
| `VISIT_QUEUE_MAX_BACKLOG` | `10000` | 1 to 1000000 | Sampled pending-visit count that triggers temporary backpressure. |
| `DATABASE_CONNECT_TIMEOUT_SECONDS` | `10` | 1 to 120 | Opening a database connection. |
| `DATABASE_IDLE_TIMEOUT_SECONDS` | `20` | 1 to 3600 | Retire idle connections. |
| `DATABASE_MAX_LIFETIME_SECONDS` | `1800` | 60 to 86400 | Recycle connections. |
| `DATABASE_STATEMENT_TIMEOUT_MS` | `10000` | 100 to 300000 | SQL execution deadline. |
| `DATABASE_LOCK_TIMEOUT_MS` | `3000` | 100 to 300000 | Lock wait deadline. |
| `DATABASE_IDLE_TRANSACTION_TIMEOUT_MS` | `15000` | 100 to 300000 | Abandoned-transaction deadline. |
| `ACCOUNT_STORAGE_BYTES` | `100MB` (100 MiB) | Positive size in bytes or with a unit, or `unlimited` | Per-account paste content budget, trash included. |
| `ACCOUNT_PASTE_LIMIT` | `1000` | Positive whole number or `unlimited` | Per-account paste count, trash included. |
| `VIEW_HISTORY_RETENTION_DAYS` | `90` | 60 to 3650 | Daily view history kept for the charts. |
| `ANALYTICS_RETENTION_DAYS` | `180` | 180 to 3650 | Daily analytics rollups kept. |
| `PURGE_BATCH_SIZE` | `500` | 1 to 5000 | Most rows deleted per batch by the hourly cleanup. |
| `PURGE_TIME_BUDGET_MS` | `2000` | 100 to 60000 | How long one cleanup run may keep starting new batches. |
| `ANALYTICS_ROLLUP_TIME_BUDGET_MS` | `2000` | 100 to 60000 | How long one analytics rollup run may keep starting new batches. |
| `HIGHLIGHT_CACHE_BYTES` | `33554432` | 0 to 256 MiB | Syntax-highlight cache per process; `0` turns it off. |
| `SLOW_QUERY_MS` | `500` | 1 to 60000 | Threshold for slow-query log events. |
| `MIGRATIONS_DIR` | set by the image | n/a | Where migrations are read from at startup. Leave unset outside the image. |

Set either account limit to `unlimited` or `0` to remove that limit. Trash and expired pastes are
removed after 30 days by a cleanup that runs at startup and hourly.

## Monitoring

| Variable | Default | What it does |
| --- | --- | --- |
| `METRICS_TOKEN` | unset | Operator credential for `GET /api/metrics` and `POST /api/jobs/{name}` maintenance writes. Metrics include latency, query counts, memory, event-loop delay, database size, and job success/failure/overdue state. Jobs are `purge`, `analytics`, `usage`, and `email`. Without a token both endpoints return 404. Keep it in an operator secret store, restrict access, and scrape every replica. Job status is per process and resets on restart. |
| `POSTHOG_KEY`, `POSTHOG_HOST` | unset, `https://us.i.posthog.com` | PostHog product analytics, off unless a key is set. Cookieless, no session replay, events never include paste content or links' slugs. `POSTHOG_HOST` picks the region (`https://eu.i.posthog.com` for the EU). |

The Analytics page inside the app counts views, copies and referrers in your own database; nothing
is sent anywhere else.

## Support and feedback

**Feedback** in the account menu works without any of these settings: it opens a prefilled
GitHub issue at `HELP_URL`, and the instance sends nothing anywhere. Set the Linear variables to
receive reports in your own tracker, and an Anthropic key to add the support assistant. See
[Get help and report a bug](/support) for what people see and what each report contains.

| Variable | Default | What it does |
| --- | --- | --- |
| `LINEAR_API_KEY` | unset | A Linear API key that can create issues and upload files. With `LINEAR_TEAM_ID`, reports are sent from the server and filed as Linear issues. |
| `LINEAR_TEAM_ID` | unset | The team to file in, by key (`WRK`) or ID. Reports land in the team's Triage state when triage is on, with its `Bug` or `Feedback` label when one exists. Bugs start at Medium priority and feedback without one. |
| `LINEAR_PROJECT_ID` | unset | The ID of a project to add every report to. |
| `ANTHROPIC_API_KEY` | unset | Turns on the **Ask** tab with Claude. Each question sends the docs, the conversation and the report details to Anthropic's API, billed to this key. With the Linear settings, the assistant can also file reports. |
| `OPENAI_API_KEY` | unset | Turns on the **Ask** tab with an OpenAI model instead. It sends the same data to OpenAI's API, billed to this key, and needs `SUPPORT_MODEL`. |
| `SUPPORT_PROVIDER` | the provider whose key is set | `anthropic` or `openai`. Needed only when both keys are set, because Anthropic is used otherwise. |
| `SUPPORT_MODEL` | `claude-haiku-5-5` with Anthropic, none with OpenAI | The model the assistant uses, such as a Claude model ID or an OpenAI model ID. The docs come first in every request, so both providers can reuse their prompt cache for repeat questions instead of paying full price for the docs again. |

Each account can send 10 reports an hour and ask 10 questions a day,
with each question limited to 300 characters. The daily count resets 24 hours after the account's
first question of the period. A report that repeats an open issue,
the same kind of report from the same page with the same opening words, becomes a comment on that
issue. Failures are logged as `support:` lines in the server log.

## Build-time settings

These are Docker build arguments for people building the image themselves, not runtime settings.
`DEPLOYMENT_VERSION` (a commit SHA) sets Next's deployment id, so all replicas of a release agree.
For independently built replicas, a stable Server Actions key can be passed as a BuildKit secret,
`server_actions_key`. You don't need either when running the published image.
