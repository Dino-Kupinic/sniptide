title: Configuration
description: Every setting Sniptide reads from the environment, with its default.

Sniptide is configured with environment variables, read when the server starts (not baked into the
image). They are checked together at startup: a value the app can't understand stops the server
with the variable's name, instead of silently using a default. A variable that is set but empty
counts as unset.

The reference file is `apps/web/.env.example` in the repository, and a test fails when the app
reads a variable that file doesn't list. Compose and the Coolify template pass these through.

## Required

| Variable | Default | What it does |
| --- | --- | --- |
| `DATABASE_URL` | none | Postgres connection string, `postgres://user:password@host:5432/sniptide`. Postgres 17 is what Sniptide is tested against. Compose sets it for you. |
| `BETTER_AUTH_SECRET` | none | Signs sessions and, unless `ENV_SECRETS_KEY` is set, encrypts env group values. Generate with `openssl rand -hex 32` and keep it across restarts: changing it signs everyone out and makes stored env values unreadable. |
| `BETTER_AUTH_URL` | none | The exact URL people open in the browser (`https://…` behind a proxy). The app boots without it, but sign-in and sign-up are rejected from any other origin ("Invalid origin"), and OAuth callbacks and printed links use it. |

## Sign-in and sign-up

| Variable | Default | What it does |
| --- | --- | --- |
| `ALLOW_SIGN_UP` | `true` | `false` closes sign-up for everyone; existing accounts keep signing in. It wins over `ALLOWED_EMAILS`. |
| `ALLOWED_EMAILS` | unset | Comma-separated emails that may sign up (invite-only). New password accounts need SMTP email verification before signing in; without SMTP, only verified OAuth identities can join. Existing accounts keep signing in. |
| `HOME_URL` | unset | The logo on the sign-in screens links here, for example to your landing page. Unset, the logo is not a link. |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | unset | Turn on GitHub sign-in. Until both are set the button shows as disabled. Callback URL: `<BETTER_AUTH_URL>/api/auth/callback/github`. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | unset | Turn on Google sign-in. Callback URL: `<BETTER_AUTH_URL>/api/auth/callback/google`. |
| `BETTER_AUTH_TRUSTED_ORIGINS` | unset | Extra origins allowed to call the auth API, comma-separated, besides `BETTER_AUTH_URL`. |
| `COOKIE_DOMAIN` | unset | Share the session cookie with other subdomains. Leave unset on one domain. |
| `COOKIE_PREFIX` | `better-auth` | Prefix for the auth cookies' names (letters, digits, `-`, `_`). Set a different one on a deployment that shares a parent domain with another one (a preview next to production). Changing it signs everyone out. |
| `DEMO_MODE` | `false` | A public demo: every visitor is signed in to one shared guest account with example data, reset on a schedule. Pastes made in the demo are visible to every visitor and deleted at the next reset. Use it with `ALLOW_SIGN_UP=false` so the guest is the only account. |
| `DEMO_RESET_MINUTES` | `60` | With `DEMO_MODE`, minutes between resets (5 to 1440). The guest is also reset at server start. |

Existing email and password accounts keep signing in. Pending invitations remain blocked until
their email is verified, even if the invite list or SMTP is later disabled. See also
[closing sign-up](/getting-started/self-hosted).

GitHub and Google sign-in require your own OAuth app credentials and the callback URLs listed
above.

## Account menu links

`HOMEPAGE_URL`, `DOCS_URL`, and `HELP_URL` override the account menu links.
By default they point to the Sniptide project.

## Pastes and sharing

| Variable | Default | What it does |
| --- | --- | --- |
| `MAX_PASTE_SIZE` | `1MB` | The most one paste can hold, across its files. Plain bytes or a number with a unit (`B`, `KB`, `MB`, `GB`, binary: 1 KB = 1024 bytes): `1MB`, `512KB`, `1.5MB` and `1048576` all work. |
| `SHARE_URL` | unset | Domain share links use when it differs from the app's. Leave unset to serve everything on one domain. |
| `SHARE_PROXY_SECRET` | unset | Shared with a separate share-domain site that proxies share pages to the app, so it can pass the visitor's IP. |
| `GITHUB_TOKEN` | unset | A GitHub token (no scopes needed) for gist imports. Without it the server shares GitHub's unauthenticated quota of 60 requests an hour. |
| `SLACK_WEBHOOK_URL`, `DISCORD_WEBHOOK_URL` | unset | Incoming webhooks for Share → Share to Slack/Discord. One channel per provider; every signed-in paste owner can post to it (20 shares an hour per account). Keep the URLs secret. |
| `ENV_SECRETS_KEY` | derived from `BETTER_AUTH_SECRET` | Key (at least 32 characters) that encrypts env group values. Set it before rotating the auth secret; changing whichever key is in use makes stored env values unreadable until they're pushed again. |

### Separate share domain

Point the share domain at the same container as the app, then set `SHARE_URL` to its HTTPS URL.
Copied links use that domain. Share pages and raw files stay on it, while app pages redirect to `BETTER_AUTH_URL`.
If another site proxies the share domain, route `/secret-share/*` to the app as well as paste links.
Separate instances can use the same slug. Duplicate slugs within one database are rejected.

### Link preview videos

Discord, Telegram and Facebook play an og:video in a public paste's link preview: the preview
card with the Game of Life moving at its sides. Other apps show the still card. The server
renders a paste's video with ffmpeg the first time its page opens, which takes about four
seconds of one core, and keeps it on disk until the paste changes. The Docker image includes
ffmpeg; without it pages leave out og:video and nothing else changes.

| Variable | Default | What it does |
| --- | --- | --- |
| `PREVIEW_VIDEO` | on | `off` leaves og:video out even when ffmpeg is installed. |
| `FFMPEG_PATH` | `ffmpeg` | The ffmpeg binary, when it isn't on the `PATH`. |
| `PREVIEW_VIDEO_DIR` | the system temp folder | Where rendered videos are cached. Mount a volume here to keep them across restarts. |
| `PREVIEW_VIDEO_CACHE_FILES` | `500` | The most videos kept (1 to 100000, about 1.6 MB each); the oldest go first. |

## Email

Notification emails are off until you configure SMTP. In-app notifications and password sign-in
work without it. Set the host, port and sender together, plus `BETTER_AUTH_URL` and a
`BETTER_AUTH_SECRET` of at least 32 characters. Users verify their address and opt in per event in
**Settings → Notifications**.

The same SMTP settings enable password reset emails. Without SMTP, the forgot-password page asks
people to contact the administrator.

| Variable | Default | What it does |
| --- | --- | --- |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM` | unset | Server, port and sender address. All three are needed. |
| `SMTP_USER`, `SMTP_PASSWORD` | unset | Credentials; supply both or neither. |
| `SMTP_SECURE` | `false` | `true` for implicit TLS (port 465). |
| `SMTP_REQUIRE_TLS` | `true` | Require STARTTLS otherwise. Only set `false` for a trusted local test server. |

### Email delivery

Email runs independently once a minute and uses a durable queue with bounded retries. Events older
than 24 hours are skipped, including events queued while SMTP was unavailable. Delivery rechecks
consent and access, and messages contain generic activity text with links to the signed-in app.
Each email includes a confirmation link that stops only that event's emails. Opening it does not
change preferences. Email is delivered at least once when retries succeed; a crash after SMTP
acceptance and before recording success can cause a duplicate. A concurrent access change can
still allow an already sending generic email to arrive.

## Client IP

| Variable | Default | What it does |
| --- | --- | --- |
| `CLIENT_IP_SOURCE` | `direct` | Where rate limits get the visitor's IP: `direct`, `x-forwarded-for`, `x-real-ip` or `cloudflare`. |
| `TRUSTED_PROXIES` | unset | With `x-forwarded-for`: the proxies' addresses or ranges (`private` covers loopback and Docker's private ranges). |
| `TRUSTED_PROXY_HOPS` | `1` | With `x-forwarded-for` and no list: how many proxies append to the header. |

Pick these to match what sits in front of the app: see [Reverse proxy and client IP](/self-hosting/reverse-proxy).

## Database and capacity

Each process uses its configured pool and can open one dedicated live-update listener. Budget for
replicas × (pool size + 1), plus migration and admin connections, within Postgres' connection limit.
Invalid values stop the server with the allowed range.

| Variable | Default | Range | What it does |
| --- | --- | --- | --- |
| `DATABASE_POOL_SIZE` | `10` | 1 to 100 | Connections per process. |
| `HTTP_ADMISSION_LIMIT` | `64` | 1 to 1024 | Active ordinary dynamic requests per process. Excess requests receive 503. |
| `PROBE_ADMISSION_LIMIT` | `2` | 1 to 16 | Active health and metrics requests. |
| `LIVE_ADMISSION_LIMIT` | `128` | 1 to 4096 | Active live-update streams, separate from ordinary requests. |
| `DATABASE_PROBE_RESERVE` | `1` | 1 to 16 | Reserved database execution capacity for probes. |
| `DATABASE_MAINTENANCE_RESERVE` | `1` | 1 to 16 | Reserved database execution capacity for background jobs. |
| `DATABASE_ADMISSION_QUEUE_LIMIT` | `64` | 0 to 4096 | Maximum waiting database submissions per process. |
| `VISIT_DRAIN_BATCH_SIZE` | `500` | 1 to 5000 | Maximum ordinary visits applied per drain batch. |
| `VISIT_QUEUE_MAX_LAG_MS` | `30000` | 1000 to 3600000 | Pending-visit age that triggers temporary backpressure. |
| `VISIT_QUEUE_MAX_BACKLOG` | `10000` | 1 to 1000000 | Sampled pending-visit count that triggers temporary backpressure. |
| `DATABASE_CONNECT_TIMEOUT_SECONDS` | `10` | 1 to 120 | Opening a database connection. |
| `DATABASE_IDLE_TIMEOUT_SECONDS` | `20` | 1 to 3600 | Retire idle connections. |
| `DATABASE_MAX_LIFETIME_SECONDS` | `1800` | 60 to 86400 | Recycle connections. |
| `DATABASE_STATEMENT_TIMEOUT_MS` | `10000` | 100 to 300000 | SQL execution deadline. |
| `DATABASE_LOCK_TIMEOUT_MS` | `3000` | 100 to 300000 | Lock wait deadline. |
| `DATABASE_IDLE_TRANSACTION_TIMEOUT_MS` | `15000` | 100 to 300000 | Abandoned-transaction deadline. |
| `ACCOUNT_STORAGE_BYTES` | `1073741824` | 524288 to 1 TiB | Per-account paste content budget. |
| `ACCOUNT_PASTE_LIMIT` | `10000` | 1 to 1000000 | Per-account paste count, trash included. |
| `VIEW_HISTORY_RETENTION_DAYS` | `90` | 60 to 3650 | Daily view history kept for the charts. |
| `ANALYTICS_RETENTION_DAYS` | `180` | 180 to 3650 | Daily analytics rollups kept. |
| `PURGE_BATCH_SIZE` | `500` | 1 to 5000 | Most rows deleted per batch by the hourly cleanup. |
| `PURGE_TIME_BUDGET_MS` | `2000` | 100 to 60000 | How long one cleanup run may keep starting new batches. |
| `HIGHLIGHT_CACHE_BYTES` | `33554432` | 0 to 256 MiB | Syntax-highlight cache per process; `0` turns it off. |
| `SLOW_QUERY_MS` | `500` | 1 to 60000 | Threshold for slow-query log events. |
| `MIGRATIONS_DIR` | set by the image | n/a | Where migrations are read from at startup. Leave unset outside the image. |

Trash and expired pastes are removed after 30 days by a cleanup that runs at startup and hourly.

## Monitoring

| Variable | Default | What it does |
| --- | --- | --- |
| `METRICS_TOKEN` | unset | Operator credential for `GET /api/metrics` and `POST /api/jobs/{name}` maintenance writes. Metrics include latency, query counts, memory, event-loop delay, database size, and job success/failure/overdue state. Jobs are `purge`, `analytics`, `usage`, and `email`. Without a token both endpoints return 404. Keep it in an operator secret store, restrict access, and scrape every replica. Job status is per process and resets on restart. |
| `POSTHOG_KEY`, `POSTHOG_HOST` | unset, `https://us.i.posthog.com` | PostHog product analytics, off unless a key is set, so a self-hosted instance sends nothing. Cookieless, no session replay, events never include paste content or links' slugs. `POSTHOG_HOST` picks the region (`https://eu.i.posthog.com` for the EU). |

The Analytics page inside the app counts views, copies and referrers in your own database; nothing
is sent anywhere else.

## Build-time settings

These are Docker build arguments for people building the image themselves, not runtime settings.
`DEPLOYMENT_VERSION` (a commit SHA) sets Next's deployment id, so all replicas of a release agree.
For independently built replicas, a stable Server Actions key can be passed as a BuildKit secret,
`server_actions_key`. You don't need either when running the published image.
