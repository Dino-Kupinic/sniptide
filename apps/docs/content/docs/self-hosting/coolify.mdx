[Coolify](https://coolify.io) can run Sniptide from a service template that includes the app and
its Postgres database. Coolify generates the database credentials and the auth secret and assigns
the domain, so nothing needs filling in before the first deploy.

## Deploy the template

1. In a Coolify project, choose **Add Resource**, then **Docker Compose Empty**.
2. Paste the contents of `deploy/coolify/sniptide.yaml` from the repository.
3. Set the domain for the `sniptide` service, on port 3000.
4. Deploy.

## Check the deployment

Coolify shows the `sniptide` service as healthy once its health check passes. The check calls
`/api/health` every 10 seconds after a 30-second start period. Open
`https://<your-domain>/api/health` and confirm it returns `{"ok":true}`, then create your
account at `https://<your-domain>`.

## What the template sets

- The image `ghcr.io/dino-kupinic/sniptide:latest` and `postgres:17-alpine`, with the database in
  the `sniptide-postgres-data` volume.
- `BETTER_AUTH_SECRET`, generated by Coolify, and `BETTER_AUTH_URL`, from the domain you assign.
- `ALLOW_SIGN_UP=first`, so sign-up closes once your own account exists. Set it to `true` to let
  anyone sign up.
- `CLIENT_IP_SOURCE=x-forwarded-for` and `TRUSTED_PROXIES=private`, because Coolify's proxy appends
  the visitor's address to `X-Forwarded-For`. See
  [Reverse proxy and client IP](/self-hosting/reverse-proxy).
- Memory ceilings through `SNIPTIDE_MEMORY` and `POSTGRES_MEMORY`, unset by default. See
  [Memory](/self-hosting/memory).

## Change settings

The template lists the common optional settings as variables on the resource: sign-up, demo
mode, GitHub and Google sign-in, `MAX_PASTE_SIZE`, account limits, database capacity,
`GITHUB_TOKEN`, Slack and Discord webhooks, SMTP and `POSTHOG_KEY`. Set the ones you need from
[Configuration](/self-hosting/configuration) and redeploy.

Other settings, such as `ENV_SECRETS_KEY`, `SHARE_URL`, `METRICS_TOKEN`, `COOKIE_PREFIX` and the
legal links, aren't in the template. To use one, add it to the `environment` list of the
`sniptide` service in the template, for example `- METRICS_TOKEN=${METRICS_TOKEN}`, then set its
value and redeploy.

The template follows Coolify's one-click service format, with a logo in
`deploy/coolify/sniptide.svg`. It isn't in Coolify's one-click list yet, so paste it as described
above.

## Back up and upgrade

The template doesn't schedule backups. Add the backup container from
`deploy/coolify/backup-sidecar.yaml` to it, and copy the files off the server. See
[Backups and restore](/self-hosting/backups).

To upgrade, take a backup, then redeploy the service so it pulls a newer image. See
[Upgrading](/self-hosting/upgrading#upgrade-the-instance).

## Images from repository CI

Repository CI publishes tested amd64 images for commits on `main` and trusted pull requests.
A successful publishing job reports its image tag and digest in the workflow summary. Publishing these images does not deploy them to Coolify or create previews by default. The template above continues to use the latest stable release image.
Operators who configure a separate image-based application should pin a registry digest, provide
runtime settings and an isolated database for previews, and manage preview creation and removal.
Repository operators can configure the opt-in production workflow described in the guide below.
See the [container publishing guide](https://github.com/Dino-Kupinic/sniptide/blob/main/docs/development.md#container-publishing)
for image tags and rollout constraints.
