`docker-compose.yml` in the repository runs the published Sniptide image next to Postgres. For a
first run from zero, follow [Run your own Sniptide](/getting-started/self-hosted). This page
describes what Compose runs and the options it takes.

## Services

| Service | What it runs |
| --- | --- |
| `db` | `postgres:17-alpine`, with data in the `postgres` volume. Published only on `127.0.0.1`, so it isn't reachable from outside the host. |
| `app` | The Sniptide image on port 3000. It waits until the database is healthy and applies migrations when it starts. |
| `proxy` | Optional [Caddy](https://caddyserver.com) for HTTPS. Runs only with the `proxy` profile, from `COMPOSE_PROFILES=proxy` in `.env` or `--profile proxy`. |

Containers write JSON log files capped at three files of 10 MB each, so logs don't fill the disk.

## Settings

Compose reads `.env` next to `docker-compose.yml`. It refuses to start without
`BETTER_AUTH_SECRET`. Set `BETTER_AUTH_URL` to the exact address people open in the browser, or
set `SNIPTIDE_DOMAIN` and leave it unset. The [install script](/self-hosting/install-script) writes
`.env` for you.
The root `.env.example` lists settings for the bundled stack. For app settings that the Compose
file doesn't pass through, such as `NOTIFICATION_EMAIL_CONCURRENCY` or `TERMS_URL`, use an
override file.

These settings belong to Compose itself:

| Variable | Default | What it does |
| --- | --- | --- |
| `SNIPTIDE_IMAGE` | `ghcr.io/dino-kupinic/sniptide:latest` | The image to run. Pin a release, such as `…:1.2.3`, for repeatable deployments. See [Versions and releases](/self-hosting/versions). |
| `SNIPTIDE_BIND` | `0.0.0.0` | The address the app's port is published on. Use `127.0.0.1` when a proxy on the same host is the only way in. |
| `SNIPTIDE_PORT` | `3000` | The host port for the app. |
| `POSTGRES_PASSWORD` | `sniptide` | The password for the bundled Postgres. It takes effect on the first start only, because the database keeps the password it was created with. Use letters and digits, since it goes into a connection URL. |
| `POSTGRES_PORT` | `5432` | The port Postgres uses on `127.0.0.1`. |
| `SNIPTIDE_MEMORY` | `0` (no limit) | A memory ceiling for the app container. See [Memory](/self-hosting/memory). |
| `POSTGRES_MEMORY` | `0` (no limit) | A memory ceiling for Postgres. |
| `SNIPTIDE_DOMAIN` | unset | The public domain. Caddy gets its certificate, and the app defaults `BETTER_AUTH_URL` to `https://<SNIPTIDE_DOMAIN>`, `CLIENT_IP_SOURCE` to `x-forwarded-for` and `TRUSTED_PROXIES` to `private`. A value you set for one of those wins. |
| `COMPOSE_PROFILES` | unset | Read by Compose itself. `proxy` starts the bundled Caddy proxy with every `docker compose up -d`. |

Settings in `.env` take effect when you run `docker compose up -d` again, which recreates the
containers whose settings changed.

## Pass through an extra app setting

Create `docker-compose.override.yml` beside `docker-compose.yml`, then add the setting under
`services.app.environment`. For example, to send up to three notification emails at once:

```yaml title="docker-compose.override.yml"
services:
  app:
    environment:
      NOTIFICATION_EMAIL_CONCURRENCY: "3"
```

With the default file discovery, Compose loads both files when you run `docker compose up -d`.
If you select Compose files with `-f` or `COMPOSE_FILE`, include the override in that list.
For secrets, reference the value from `.env` instead of writing it in the override, for example
`LINEAR_API_KEY: ${LINEAR_API_KEY:-}`. The install script leaves the override file in place.

## Add HTTPS with the bundled proxy

1. Point the domain's DNS at the server and open ports 80 and 443.
2. Remove `BETTER_AUTH_URL` from `.env` and add these lines:

   ```dotenv title=".env"
   SNIPTIDE_DOMAIN=paste.example.com
   COMPOSE_PROFILES=proxy
   SNIPTIDE_BIND=127.0.0.1
   ```

   Keep `SNIPTIDE_BIND=127.0.0.1` or block direct access with your firewall. Public requests must
   pass through Caddy so the app can trust the forwarded client address.
3. Apply the change:

   ```bash
   docker compose up -d
   ```

4. Open `https://paste.example.com/api/health` and confirm it returns `{"ok":true}`.

Caddy gets and renews a Let's Encrypt certificate and keeps it in the `caddy-data` volume.
`SNIPTIDE_DOMAIN` also sets the app's public address to `https://paste.example.com`, and makes rate
limits read the visitor's address from the `X-Forwarded-For` header that Caddy adds, trusted only
from private addresses.
See [Reverse proxy and client IP](/self-hosting/reverse-proxy). If you already run nginx,
Traefik or Coolify, skip the profile and put your proxy in front of port 3000.

## Operate the stack

```bash
docker compose ps                  # state and health of each service
docker compose logs -f app         # the app writes one line per request
docker compose pull && docker compose up -d   # upgrade, see Upgrading
docker compose down                # stop, keeping the data
```

`docker compose down -v` also deletes the `postgres` volume with all data. Take a
[backup](/self-hosting/backups) first.

To build the image from source instead of pulling it, run `docker compose up -d --build`. A build
needs 2 GB of memory or more, so pull the published image on a small server.
