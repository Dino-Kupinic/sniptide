Sniptide runs as one container next to a Postgres database. A self-hosted instance has the same
app, API, CLI support and MCP server as the hosted one. Product analytics, external sign-in
providers and email are off until you configure them. Importing a gist sends a request to GitHub
even without a GitHub token.

- **App container:** Next.js and React serve the dashboard, paste links, HTTP API and remote MCP
  endpoint. Better Auth handles sign-in and browser sessions. Sniptide issues and refreshes agent
  tokens through its own OAuth endpoints. Maintenance jobs run in the same app process.
- **Database:** Drizzle connects the app to Postgres. Paste files, revisions, accounts, tokens,
  analytics and durable queued work live there. The Compose volume keeps that data across
  container replacements. Keep a [database backup](/self-hosting/backups) as well.
- **HTTPS proxy:** Caddy forwards requests to the app on port 3000. You can use
  [your own reverse proxy](/self-hosting/reverse-proxy), or let
  [Coolify](/self-hosting/coolify) provide it.
- **Optional integrations:** OAuth providers, SMTP email, PostHog, webhooks and support providers
  connect only when configured. See [Configuration](/self-hosting/configuration).

Marketing, the hosted demo and the documentation site run separately from the hosted app. You
don't need to deploy those sites to run your own instance.

## Before you begin

- A server with Docker, plus the Compose plugin for the Compose route. The image is
  `ghcr.io/dino-kupinic/sniptide`, for Linux AMD64 and ARM64.
- Postgres 17, which Sniptide is built and tested against. Compose and the Coolify template run
  their own.
- Memory for the app and Postgres sized for your workload. See
  [Memory and resources](/self-hosting/memory) for what to monitor and how to set limits.
- An HTTPS domain served at its root, such as `https://paste.example.com`. Serving the app under a
  path such as `/sniptide` isn't supported.
- Two settings: `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL`. See
  [Configuration](/self-hosting/configuration#required).

## Choose an install

| Install | Use it when | Database |
| --- | --- | --- |
| [Install script](/self-hosting/install-script) | You start from an empty server and want one command. It sets up Docker Compose and HTTPS for you. | Runs Postgres for you |
| [Docker Compose](/self-hosting/docker-compose) | You start from an empty server. Includes an optional HTTPS proxy. | Runs Postgres for you |
| [Docker](/self-hosting/docker) | You already run Postgres and want only the app container. | Yours |
| [Coolify](/self-hosting/coolify) | You manage services in Coolify. It fills in the secret and domain. | Runs Postgres for you |

For a first run from zero, run the install script, or follow
[Run your own Sniptide](/getting-started/self-hosted) to do the same steps by hand.

## How the app starts

On startup Sniptide applies its database migrations before it serves requests, so there is no
separate setup step. `GET /api/health` returns `{"ok":true}` when the server and database answer,
and the image runs a Docker health check against it.

## Addresses and HTTPS

Set `BETTER_AUTH_URL` to the public address people open, and have your reverse proxy forward the
public host and scheme. On a single domain, leave `SHARE_URL` and `COOKIE_DOMAIN` unset.

Plain HTTP on the server's address is enough to check that it starts. Copy buttons and password
unlocks need HTTPS in the browser, and the CLI and local MCP server refuse HTTP except on
`localhost`. Add the [bundled HTTPS proxy](/self-hosting/docker-compose#add-https-with-the-bundled-proxy)
or your own [reverse proxy](/self-hosting/reverse-proxy) before you share pastes.

## Connect clients to your instance

Clients default to the hosted app, so point them at your instance and create their tokens there:

- Set `SNIPTIDE_BASE_URL=https://paste.example.com` for the CLI and the local MCP server, or pass
  the address as the base URL to the SDKs.
- Connect MCP clients to `https://paste.example.com/api/mcp`. OAuth sign-in works without extra
  setup, as [OAuth for agents](/oauth#self-hosted-instances) describes.

Paste links use your instance's domain. Separate instances with separate databases can use the
same link without conflict.
