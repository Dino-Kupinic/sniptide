---
title: Memory and resources
description: How much memory Sniptide needs, and the limits the image and compose set.
---

One Sniptide server sits around 100 MB idle and 250 to 300 MB under load. The defaults are sized
for a small server.

## The two limits

- **Heap cap.** The image runs Node with `NODE_OPTIONS=--max-old-space-size=384`. Without a cap
  Node sizes its heap from the host's RAM and keeps growing into it, so a server that is never
  short of memory ends up around 440 MB resident under load against about 260 MB with the cap.
- **Container ceiling.** Give the container a memory limit too (`--memory 768m` with
  `docker run`, or `SNIPTIDE_MEMORY` with compose). If the app ever reaches it, Docker restarts
  Sniptide instead of the kernel killing other processes on the server. Set the swap limit to the
  same value so a runaway restarts at the ceiling instead of thrashing.

Compose and the Coolify template set both: 768 MB for the app, 512 MB for Postgres (`POSTGRES_MEMORY`),
and the 384 MB heap.

<Callout type="warn">
`NODE_OPTIONS` replaces the whole value. If you set it to add a flag, include
`--max-old-space-size` too.
</Callout>

## On a bigger server

Raise both, keeping the heap at about half the ceiling. For example `--memory 1536m` with
`NODE_OPTIONS=--max-old-space-size=768`; in compose, set `SNIPTIDE_MEMORY=1536m` and
`NODE_OPTIONS=--max-old-space-size=768` in `.env`. Raise `DATABASE_POOL_SIZE` only after checking
Postgres' connection budget.

The syntax-highlight cache uses part of the heap (32 MB by default, `HIGHLIGHT_CACHE_BYTES`; `0`
turns it off), and actual memory use is larger than the cached size.

## Building the image is different

Building takes far more memory than running (a `next build` can use 2 GB or more). On a small
server, pull the published image instead of building there. Every PR preview on a Coolify box is
another server and database too, so budget for them.

## Watching it

Set `METRICS_TOKEN` to enable `GET /api/metrics` (memory, CPU time, event-loop delay and query
statistics per process). See [Configuration](/self-hosting/configuration#monitoring).
