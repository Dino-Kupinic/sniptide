---
title: Memory and resources
description: Default memory behavior and optional resource limits.
---

The image leaves `NODE_OPTIONS` unset, so Node uses its normal heap sizing. The Compose and
Coolify templates do not impose fixed RAM ceilings by default. Your hosting platform can still
apply its own resource limits.

## Optional limits

Set `SNIPTIDE_MEMORY` for the app container or `POSTGRES_MEMORY` for the database when you want
an explicit ceiling. Both default to `0`, which leaves the template's ceiling unset. You can also
supply Node flags through `NODE_OPTIONS`, including an explicit heap size when needed.

Heap size is only part of the app's memory use. Leave room for native buffers, syntax highlighting,
active requests and the database when choosing limits. Resource needs depend on your workload.

## Remove old overrides

Older images and templates supplied a fixed Node heap cap and small container ceilings. If an
existing Coolify resource or `.env` file still sets `NODE_OPTIONS`, `SNIPTIDE_MEMORY` or
`POSTGRES_MEMORY`, clear those values or set the container ceilings to `0`, then redeploy.
Updating the template does not remove saved deployment overrides.

## Build memory

A production build needs more memory than a running app. On a small server, pull the published
image instead of building it there. Each preview deployment also runs its own app and database.

## Monitor resources

Set `METRICS_TOKEN` to enable `GET /api/metrics`, which reports process memory, CPU time,
event-loop delay and query statistics. See [Configuration](/self-hosting/configuration#monitoring).
